# Test coverage

Scope: Azure IoT C SDK (`c/`). One table per feature area.

| Column | Meaning |
| --- | --- |
| Group | Scenario family; shown once, on the first row of the group. |
| Test | Human-readable test name (maps 1:1 to the test function name). |
| Scenario | Extra detail only when needed; never repeats Group, Test or Type. `—` when there is nothing to add. |
| Type | Test tier: `unit`, `conformance` or `e2e`. |
| Status | `Done` = implemented and running in CI. `Pending` = not implemented. |
| Code Location | Implementing function, deep-linked to its definition line on `main`. Pending rows name the file the test belongs in. |

Types: **unit** = cmocka + fake MQTT adapter, no network (`c/tests/unit`); **conformance** = live MQTT broker via `AZ_IOT_MQTT_BROKER_HOST`, no Azure service (`c/tests/conformance`); **e2e** = real DPS + IoT Hub with the Paho adapter (`c/tests/e2e`). There is no separate `integration` tier — `conformance` fills that role.

Certificate issuance and CSR renewal are tracked in a future *Certificate management* section; only the connect-time gating of those options appears here.

## Known gaps

Defects and limitations found while building the coverage above. Each `Pins defect`
row in the table locks in the **current** behaviour so that changing it produces a
visible test diff rather than a silent one.

| Id | Severity | Finding |
| --- | --- | --- |
| C-1 | Medium | `close()` during CONNECTING is overridden by a CONNACK already in flight. The CONNACK handler calls `announce_connected()` without consulting `user_close` (it is only checked on the failure branch), so the app is told CONNECTED after it asked to close, and anything publishing on CONNECTED writes into a socket being torn down. The session does settle to IDLE afterwards. Fix: bail out of the success branch when `user_close` is set or the state is no longer CONNECTING. |
| C-2 | Medium | `AZ_IOT_ERR_IDENTITY_REJECTED` has **no** special handling. `az_iot_mqtt_iface.h` documents it as the code that "makes the SDK re-provision through DPS instead of retrying an identity the broker has already refused", and the CONNACK mapping faithfully produces it — but `connection_client.c` never reads it, so a device with a revoked identity retries the refused credential until `max_attempts`. Either implement re-provisioning or correct the header. |
| C-3 | Low | In-flight QoS-1 publish callbacks are dropped, not completed, when a session ends. `teardown_active()` clears every `pending_pubacks` slot without invoking the callbacks, so an app tracking outstanding publishes leaks one entry per unacknowledged publish on every reconnect and is never told to resend. Completing them with an error would make retry deliberate. |
| C-4 | Low | An unparsable DPS registration response is skipped silently — no fault, no re-poll, no diagnostic. The client sits in CONNECTING until the application gives up on its own. |
| C-5 | **High** | A NULL or empty `dps.registration_id` (with a valid `dps.id_scope`) makes `az_iot_connection_client_open()` **hang forever**. `dps_configured()` checks only `id_scope`, so the empty value reaches `az_iot_provisioning_client_init()`, and this build has `AZ_NO_PRECONDITION_CHECKING=OFF` with no precondition handler installed — az_core's default is an infinite `while(1)` loop. A misconfigured device wedges the calling thread with no error and no crash to diagnose. This is why the corresponding test is absent rather than failing: it would hang CI. Fix: validate the DPS identity in `open()` (and/or install a precondition handler). |
